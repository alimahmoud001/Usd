# Usd

تطبيق محفظة كريبتو (MVP) — واجهة Flutter (APK)

نظرة عامة
- الشبكة: Binance Smart Chain (BSC) — BEP-20 (USDT على BEP-20). لا يتم استخدام ERC-20.
- تقنية الواجهة: Flutter (Dart) — يسمح ببناء APK واحد يعمل على Android.
- التشفير: المفاتيح الخاصة تُخزن مشفّرة محليًا. نستخدم PBKDF2 لتوليد مفتاح التشفير و AES‑GCM للتشفير/فك التشفير (يمكن استبداله بـ Argon2 لاحقًا إذا لزم).
- توقيع المعاملات: يتم محليًا بعد فك تشفير المفتاح بإدخال كلمة سر المحفظة. المفتاح لا يلمس الإنترنت.

ما تم إضافته هنا
- ملف GitHub Actions لبناء APK تلقائيًا: .github/workflows/build_apk.yml (سيتم إضافته في التزامات لاحقة)
- ملف إعدادات Flutter: pubspec.yaml (مهيأ)
- ملف تطبيق Flutter مبدئي: lib/main.dart (MVP مبدئي)
- README محدث مع تعليمات البناء والتشغيل

كيف تبني APK محليًا
1. ثبّت Flutter (النسخة المستحسنة: stable channel). راجع https://flutter.dev
2. من جذر المستودع شغّل:
   flutter pub get
   flutter create .
   flutter build apk --release
3. ستجد الـ APK في build/app/outputs/flutter-apk/app-release.apk

كيف يحصل CI على APK (GitHub Actions)
- بعد الدفع إلى المستودع، سينفّذ workflow الذي يولّد APK ويحمّله كـ artifact. تقدر تنزيله من صفحة Actions في GitHub.

ملاحظات أمنيّة
- المفتاح الخاص لا يرسل لأي خادم.
- عند إضافة محفظة، يتم تشفير المفتاح محليًا مع كلمة سر خاصة بالمحفظة.
- عند التوقيع يتم طلب كلمة السر وفك التشفير محليًا فقط ثم حذف المفتاح المفكوك من الذاكرة فورًا.

ما يلي ملاحظات وتطوير لاحق
- أضفت مخطط MVP لواجهة التطبيق (قوائم المحافظ، إضافة عبر QR أو لصق، شاشة محفظة، إنشاء معاملة غير موقعة، واجهة توقيع).
- سأكمل تدقيق التشفير والتكامل مع web3dart لبث المعاملات بعد موافقتك على التفاصيل النهائية (Mainnet أو Testnet، RPC provider). حالياً العمل مهيأ لاستخدام BSC Testnet افتراضيًا.

APK في المستودع
- إن أردت، يمكنني إضافة APK debug إلى مجلد releases/ داخل المستودع أو إعداد GitHub Actions لبنائه تلقائيًا ورفع الأرتيفاكت.

تعليمات الأمان والتشغيل
- تأكد من استخدام جهاز آمن عند اختبار المفاتيح الحقيقية.
- أنصح بالبدء على Testnet قبل الانتقال إلى Mainnet.
